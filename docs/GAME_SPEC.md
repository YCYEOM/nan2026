# GAME_SPEC — 리허설: 주제 "온도"

> ⚠️ 제거됨 (2026-07-27): 씬·HeatField 시스템·테스트 삭제. 아래는 설계 기록용. 재사용 키트(Grid/DragDrop/behaviors)는 하네스에 유지.

- 주제: 온도
- 한 줄 규칙: 뜨겁고 찬 열원을 배치해, 서로 다른 온도를 원하는 생물들이 **동시에** 견디는 환경을 만든다.
- 핵심 조작(동사 1 + 보조 1): Place(열원 배치) + Move(집어 옮기기)
- 승리 조건: 모든 생물이 자기 허용 온도대에 **3초 연속** 머무름
- 실패 조건: 제한 시간(60초) 초과
- 주제 전용 규칙: 열이 그리드로 **번지고(Shared Fate)**, 열원은 스스로 **진동(Oscillate)**해 온도가 계속 흔들림 → "온도"를 빼면 규칙 자체가 사라짐
- 대표 장면: 마지막 생물이 온도대에 들어오는 순간 그리드 전체가 안정 색으로 **변태(Transformation)**
- 제외 기능: 스테이지 다수, 성장 트리, 서사

## 6축 조합 (문서 예시 D)

| 축 | 선택 |
|---|---|
| 공간 구조 | Grid |
| 핵심 동사 | Place |
| 시스템 동작 | Oscillate + (열)Propagation |
| 압박 방식 | Conflicting Goals (이웃 생물이 반대 온도를 원함) |
| 주제 결합 장치 | Shared Fate (한 배치가 주변 전체에 영향) |
| 시각적 보상 | Transformation |

## 필요한 신규 시스템 (최대 2개)

1. HeatField — 열 확산 + 진동 열원 (신규)
2. (재사용) Grid, DragDrop 키트

# GAME_SPEC — 리허설2: 주제 "전염"

> ⚠️ 제거됨 (2026-07-27): 씬·Infection 시스템·테스트 삭제. 아래는 설계 기록용.

- 주제: 전염 (Contagion)
- 한 줄 규칙: 한정된 **장벽**을 배치해, 시간차로 번지는 감염이 **성역**에 닿기 전에 절단한다.
- 핵심 조작(동사 1 + 보조 1): Cut(빈 칸 클릭 → 장벽) + Undo(장벽 클릭 → 회수)
- 승리 조건: 감염이 더 번질 곳이 없어 **멈추고(done)**, 모든 성역이 깨끗함
- 실패 조건: 성역 한 칸이라도 감염됨
- 주제 전용 규칙: 감염은 매 틱 4방향으로 **한 링씩 번짐(Spread)**, 장벽/경계에만 막힘 → "전염"을 빼면 번질 게 없어 규칙 소멸
- 대표 장면: 붉은 확산이 장벽에 부딪혀 성역 **한 칸 앞에서** 멈추는 순간(NearMiss), 화면이 감염/안전으로 갈라짐
- 압박: 예산(장벽 8개 = 세로 절단선 정확히 1줄) + 시간(링이 성역쪽으로 전진)
- 제외 기능: 스테이지 다수, 백신/치료, 확률 감염, 서사

## 6축 조합

|---|---|
| 공간 구조 | Grid |
| 핵심 동사 | Cut |
| 시스템 동작 | Spread (timed one-ring flood) |
| 압박 방식 | Time + Capacity (장벽 예산) |
| 주제 결합 장치 | Contagion (번짐 자체가 규칙) |
| 시각적 보상 | ChainReaction + NearMiss |

# GAME_SPEC — 리허설3: 주제 "전력망" (협동 + 트롤)

- 주제: 전력망 (Shared Power Grid). 로컬 핫시트 2인.
- 컨셉: **협동이 기본인데 고의든 실수든 팀원 트롤이 가능**. 온라인 멀티는 6h 밖이라 핫시트로 대체.
- 한 줄 규칙: 공유 용량을 나눠 기계를 켜서 팀 할당량을 채우되, 총부하가 용량을 넘으면 차단기가 트립돼 전원이 다 나간다.
- 핵심 조작(동사 1 + 보조): Allocate(기계 ON·OFF) + 역할 액션(차단/증설)
- 승리 조건: 45초 안에 팀 작업량 ≥ 할당량(1000)
- 실패 조건: 시간 초과
- 대표 장면: 지연 미터가 몰래 차오르다 **차단기 트립 → 전 기계 블랙아웃**, "누구 탓?" 책임 로그가 뜸

## 컨셉을 성립시키는 3속성 → 코드 매핑

| 속성 | 구현 |
|---|---|
| ① 돕는 행동 = 트롤 행동 (같은 액션) | "대" 기계 켜기 = 내 점수↑ **and** 팀 부하 위험↑. 차단=구조 or 팀원 기계 꺼버리기. 증설=밀어주기 or 아껴 방치 |
| ② 가려짐 (고의/실수 애매) | **지연 부하 미터**(displayLoad가 실제 부하를 늦게 따라옴) + **애매한 책임 로그**(초과 구간 기여를 보여주나 지연 탓에 특정 불가) |
| ③ 공동 운명 | 트립은 개인이 아니라 **팀 전원**을 내리고 팀 작업량 세트백(−15%) |

## 6축 조합

## 고도화 레이어 (구현 완료)

- **A. 개인 기여 / MVP** — 팀 점수와 별개로 owner별 원 생산량 누적(세트백 無). 종료 시 MVP. → 공유지의 비극: 이기심과 기여가 포개짐.
- **브라운아웃** — 총부하가 용량 90% 넘으면 전 기계 효율 하락(0.4까지). 과욕의 외부효과가 팀 생산을 갉음.
- **C. 비대칭 역할** — P1 `부하차단`(최대 기계 강제 OFF, 쿨 6s), P2 `증설`(용량 +45, 4s, 쿨 8s). 상호의존 = 협동 강제. + 트립 시 **책임 로그**.
- **B. 동적 압박** — 수요 급증(12s 주기 5s간 외부부하 +35, 안전조합이 이동) + 열 피드백(고부하 시 용량 서서히 하강, 식으면 회복).

## 스펙트럼 확장 — 기계 5종 + 랜덤 이벤트 3종 (구현 완료)

- **기계 5종**: 소·중·대(과욕) + **초효율**(저부하 고출력 — 협동 친화) + **불안정**(고출력, draw가 랜덤 급등 → 갑작스런 초과. 켜는 건 선택=리스크, 급등 타이밍은 랜덤=발뺌). 스파이크로 넘으면 토글 아님 → 크로서 페널티 없음(환경 처리).
- **랜덤 이벤트 3종**(9s 간격·5s 지속, seed 기반): ⚡정전폭풍(용량 −40) / 📈수요쇼크(외부부하 +50) / 🔧정비(용량 +25, 숨 돌리기).

# GAME_SPEC — 리허설4: 주제 "리듬" (협동 릴레이)

- 주제: 리듬 (Rhythm). 로컬 핫시트 2인 × 키 3개(레인 6). 인원·키 확장은 `PLAYERS`/`KEYS_PER_PLAYER`/`KEYS`/`C.player` 확장. 단 P3·P4 색은 `C.success`·`C.danger`·`C.accent`·`C.demand` 와 겹치지 않고 기존 플레이어 색과 밝기가 달라야 한다 — 제약은 DESIGN.md 색 역할표.
- 한 줄 규칙: 공통 박자에 맞춰 **한 명씩 돌아가며** 자기 차례 비트를 정확히 눌러 팀 콤보를 잇는다.
- 핵심 조작(동사 1): Timing Input(차례에 **자기 키 중 지정된 키**). P1 `S`/`D`/`F` · P2 `J`/`K`/`L` (+ M 음소거, R 재시작). 담당과 키가 둘 다 맞아야 판정된다.
- 승리 조건: 전 비트(32) 완주 시 생명>0
- 실패 조건: 팀 생명(4) 소진
- 협동 필연성: 비트가 **라운드로빈**으로 담당이 바뀌어 혼자 못 캐리. 콤보·생명이 **팀 공유** → 누구 하나 미스면 전원 손해. "리듬"을 빼면 타이밍·차례 규칙이 사라짐.
- 대표 장면: 두 사람이 번갈아 정타로 콤보를 쌓아 하이웨이가 연쇄 점등, 콤보 숫자가 치솟는 순간.

## 판정 모델 (src/systems/rhythm.ts)

- 비트 k 시각 = `leadIn + k·(60/bpm)`, 담당 = `k % players`.
- `press(player, lane)`: 자기 차례 + **키 일치** + 창 안이면 `perfect`(±0.09s)/`good`(±0.2s), 남의 차례나 틀린 키=`wrong`, 창 전=`early`(무판정, 스팸 방지).
- `step(dt)`: 창을 넘긴 비트는 `miss` → 콤보 0 + 생명 −1.
- 점수 = (perfect 100 / good 50) × min(콤보, 8). 콤보·점수·생명 전부 팀 공유.
- 메트로놈 틱(음악 없어 타이밍 앵커) — 씬에서 지나간 비트마다 Sfx.tick.
- **판정 등급별 피드백**(`feedback()`, 씬): perfect 충격파 링 2겹·파티클 22·흔들림 3.5·레인 섬광 / good 링 1겹·파티클 9·흔들림 1 / miss 링 없음·파티클 7·흔들림 8·붉은 화면 가장자리. press·release·step 세 경로가 같은 함수를 쓴다.
- **판정선이 현재 담당 플레이어 색으로 빛난다.** 화면에서 가장 큰 시각 요소가 차례를 말한다. 시그니처 그라데이션은 레인 테두리 같은 장식에만 쓴다 — 그라데이션 끝(#00E5FF)이 P1 색과 같아 상태 요소에 쓰면 차례가 모호해진다(DESIGN.md).
- **담당 표시는 리드인부터 켠다.** 하단 키 힌트(레인당 박스 1개, 총 6개)는 `!done` 이면 항상 다음 비트의 **그 키 하나**를 강조하고, 카운트다운에도 "첫 노트는 P1 — [D]"를 띄운다(그 노트의 키). 첫 노트가 이미 화면에 들어와 있는데 담당을 안 알려주면 첫 판정을 놓친다.

### 동시 비트 (합주) — 협동 심화

- `syncEvery`(기본 4)번째 비트는 담당이 **전원**(currentPlayer=-1). 모두가 창 안에 함께 눌러야 성공, 점수 `syncBonus`(×2). 하나라도 놓치면 팀 미스.
- 왜: 라운드로빈은 "각자 제 몫"이라 조율이 없음 → 동시 비트가 *같이 맞춰야 하는 순간*을 만들어 협동을 실제로 강제. 부분 등록(`sync`) 시 파트너 대기(누른 사람 ✓ 표시).
- 렌더: 시그니처 핑크 글로우를 두른 흰 큰 원 + 플레이어 색 반쪽, "동시" 라벨. 차례 표시 "◉ 동시! 모두 함께".

### 모드 — 팀전 / 개인전

- `mode: "team"`(기본): 공유 콤보·생명·점수 + 동시 비트. 완주=팀 승, 생명 소진=팀 패. **협력**.
- `mode: "solo"`(개인전): 플레이어별 점수·콤보, 동시 비트 **비활성**, 생명 없음. 곡 완주 후 **최고 점수가 승자**(`winner()`, 동점 무승부). **경쟁**.
- 메뉴에 "리듬 릴레이(팀전)" / "리듬 대결(개인전)" 두 항목으로 등록. 씬은 `new RhythmScene(h, mode)`.

### 스테이지 진행 (정확도 게이트)

- 정확도 = 가중합(perfect 1.0 / good 0.6) / 처리된 비트 × 100. HUD·종료화면에 **백분율** 표시.
- 곡을 끝까지 완주 + **정확도 ≥ 90%** → **스테이지 클리어** → 클릭/스페이스로 다음 스테이지. 미만이면 같은 스테이지 재도전(R). 팀전 생명 소진은 실패.
- 스테이지 n마다: `bpm=90+12n`, 판정창 축소(perfect −0.008n, good −0.015n), `syncEvery=max(2,4−n)`(동시 잦아짐), `holdChance=min(0.5,0.25+0.06n)` → **점점 빠르고 복잡**.
- 종료화면 진행(다음/재도전)은 pointer/key에서 처리 — harness는 phase="play"에서만 update 호출하므로.

### 현란한 연출 (변속·웨이브 + juice)

- **웨이브 궤도**: x는 **등속**(시각 도착=실제 박자 → 온타이밍 실패 없음). 노트의 **약 1/3만**(`wavy: k%3===1`) y로 굽이침, 판정선(p=0)엔 정확히 수렴. (초기엔 x도 변속했으나 도착이 실제보다 일찍 보여 `early` 오판 → 등속으로 롤백.)
- **juice**: 비트마다 레인 섬광, 정타 시 파티클 버스트, 미스/퍼펙트 시 화면 흔들림(shake). 순수 렌더 — 판정 로직 무변경.

### 멜로디 (BGM)

- 직접 작곡한 16음 펜타토닉 루프(`MELODY` 배열, `src/scenes/rhythm.ts`). 비트를 넘을 때마다 해당 음을 Web Audio 신스로 연주 → 메트로놈 대신 **음악**이 타이밍 앵커. 홀드 비트는 길게 울림.
- 펜타토닉이라 어떤 구간이 겹쳐도 안 튐 → 배열만 늘리면 곡 확장. 외부 AI 아닌 **음표 시퀀스 직접 작곡** + 신스 재생.

### 협동 홀드 · 연타 (노트 기믹)

- **협동 홀드**(owner −1 + hold>0): 전원이 start 창에 같이 누르고 **끝까지 유지 → 다같이 떼기**. 한 명이라도 일찍 떼면 팀 브레이크(미스). 점수 `syncBonus×holdBeats`. "여러명이 같이 길게" = 협동의 정점.
- **연타(mash)**(mash>0, hold=창): 담당이 창 안에서 `mash`번(3~4) 눌러 채우면 성공(횟수 보너스 ×(1+0.4·mash)). 창=1.6박 + 앞뒤 good grace(자비 완화). 남은 횟수 노트에 표시. **07-29 플레이테스트 합격 — 이 수치 확정**(`evidence/playtest-2026-07-29-mash.md`). 단 후반 스테이지(bpm +12/스테이지)는 미검증.
- 변칙 차트에서만 등장(동시류의 40%가 협동 홀드, 비동시의 12%가 연타). 균일 차트(무seed)엔 없음 → 코어 테스트 보존.
- 연타 진행 중 판정은 `mash`(화면 "연타!"). 홀드 진행 중인 `hold`("홀드 유지!")와 별도 값이다 — 연타 노트는 `hold` 필드를 창 길이로 재사용하므로 result 까지 공유하면 연타에 "홀드 유지"가 뜬다.
- (다음 후보: 번갈아 누르는 **릴레이 홀드** — 판정 상태 복잡해 보류.)

### 개인 적중률 (승패 기준)

- 변칙 차트는 담당을 `Math.floor(rnd()*players)` 로 뽑아 **P1/P2 노트 수·종류가 다르다**. 연타(×2.2~2.6)·홀드(×holdBeats) 보너스가 누구에게 가는지도 랜덤이라 **점수 비교는 실력이 아니라 차트 운을 잰다.**
- 그래서 개인 비교는 **적중률** = `pacc / pjudged × 100`. perfect 1 / good 0.6 / miss 0. solo 승자(`winner()`)도 점수가 아니라 적중률로 가린다.
- 동시류도 개인 집계에 **포함**한다. 팀이 깨지면 `tally(k, 0, did)` 의 `did` 로 자기 몫을 한 사람(1)과 안 한 사람(0)을 가른다 — 동시 탭은 `syncPressed`, 협동 홀드 조기 뗌은 먼저 뗀 `player` 가 기준.
- 팀이 깨진 경로에서 자기 몫을 한 사람에게는 타이밍 등급과 무관하게 1을 준다. 이 경로는 정밀도가 아니라 책임 소재를 재기 때문이다.
- 화면에는 항상 모수를 같이 적는다: `P1 92%(18노트·2400점)`. 비율만 보이면 표본이 작은 쪽이 유리해 보인다(DESIGN.md 원칙 4).

### 롱노트 (홀드)

- 변칙 차트의 ~25% 비트가 홀드(1~2박). 시작 창에서 누르면 `hold`(진행), 끝 시각 근처에서 **떼면** 성공(`release`) — 길수록 점수 보너스(×holdBeats). 너무 일찍 떼면 **브레이크=미스**, 끝까지 유지하면 step이 자동 성공 처리.
- 입력: 씬이 keydown=press / keyup=release로 위임. 렌더: 머리 링 + 색 꼬리(유지 중 밝게, 판정선에 머리 고정).
- **꼬리는 궤도를 따라 물결친다.** 두 끝점을 잇는 직선이 아니라 같은 `pathX`/`pathY` 를 16구간으로 샘플링한다. 홀드는 꼬리가 길어 모양이 읽히므로 `wavy(k)` 가 항상 참(탭은 1/3 규칙 유지, 연타는 꼬리가 없어 제외). 판정은 시간 기준이라 영향 없고 `p=0`(판정선)에서 정확히 수렴한다.
- 균일 차트(seed 없음)엔 홀드 없음 → 기존 탭 테스트 보존.

### 변칙 패턴 (chart)

- 생성자에서 비트 스케줄 `chart[{t, owner}]` 선계산. `seed` 없으면 **균일**(간격 일정·담당 라운드로빈=기존, 테스트 보존). `seed` 있으면 **변칙**: 간격 ∈ {1,1,1,1.5,2}박(쉼표·싱코페이션), 담당 랜덤, 동시 ~1/syncEvery 확률.
- 씬은 reset마다 새 seed → 매 판 다른 패턴. 예측 불가라 "누구 차례?"를 계속 주시해야 함 → 집중·긴장.
- 메트로놈 틱은 균일 가정 대신 실제 `beatTime`을 넘을 때마다 울림(변칙 간격 대응).

### 레인 — 플레이어당 키 여러 개 (TASK-007)

- 각 플레이어가 키 `KEYS_PER_PLAYER`(3)개를 갖는다. P1 `S`/`D`/`F`, P2 `J`/`K`/`L`
  (홈 포지션 — 왼손 약·중·검지 / 오른손 검·중·약지).
  실력 축이 하나(타이밍) → 둘(타이밍 + 어느 키)로 늘어난다.
- `Note.lane` = 담당자의 몇 번째 키인가. `press(player, lane)` 에서 **담당과 키가 둘 다**
  맞아야 판정된다. 담당은 맞고 키가 틀리면 기존 `wrong` 을 재사용한다(새 Result 없음).
- `keysPerPlayer` 를 안 주면 모든 노트가 lane 0 이고 `press(player)` 가 그대로 동작한다.
  `buildChart` 가 kpp=1 일 때 `rnd()` 를 소비하지 않아 기존 시드 차트도 보존된다.
- **동시류는 레인을 따지지 않는다.** 전원이 함께 누르는 노트라 "상대의 몇 번째 키"가
  의미 없다 → 자기 키 아무거나 된다. 렌더는 하이웨이 중앙(`MID_Y`).
- `holdLane` 을 둔다. 같은 사람이 홀드 중 **다른 키를 떼도** 홀드가 끊기지 않아야 한다 —
  `release(player, lane)` 가 lane 까지 본다. 이게 없으면 D 를 누른 채 F 를 떼면 미스가 된다.
- 화면: 하이웨이가 6레인(`LANE_H` 43, y 158~416). 레인마다 소유자 색을 5% 깔고,
  플레이어 경계선은 진하게·같은 사람 키 사이는 흐리게 그려 "내 구역"이 묶음으로 읽힌다.
- 링 반지름 배치: 노트 `RAD` 15/13 · 연타 링 `rad+2`(두께 3) · 반전 점선 링 `rad+6`(두께 2).
  연타 + 반전이 같은 노트에 걸리면 두 링이 포개져 둘 다 안 읽히므로 간격을 벌려 둔다.
- 판정선에 **레인별 표적 원**. 다음 노트가 올 레인만 담당 색으로 빛난다. 노트 라벨도
  `P1` → **키 글자**(`S`/`D`/`F`)로 바꿨다 — P1 이 키를 여럿 가지면 "P1" 은 정보가 아니다.
- 판정 팝업을 판정선 **왼쪽**(x=75), 판정된 레인 높이로 옮겼다. 노트는 `x >= HIT_X` 에만
  있어 이 구역은 구조적으로 비어 있다 → 원칙 5(장식이 판정을 가리지 않는다)를 구조로 보장.
- **웨이브 진폭 26 → 6.** `WAVE + RAD <= LANE_H/2` 를 지켜야 노트가 옆 레인을 침범하지
  않는다. 레인이 생기면서 굽이침보다 "어느 키인가"가 먼저다 — TASK-005 물결의 후퇴다.

### 반전 노트 (TASK-006)

- 노트 일부가 **반전**된다. 화면에는 상대 색으로 오지만 눌러야 하는 사람은 그대로 담당자다.
  `Note.swap` 은 **표시 색만** 바꾼다 — `ownerOf(k)` 는 계속 "눌러야 하는 사람"이라
  `press`·`release`·`tally`·`winner` 는 한 줄도 바뀌지 않는다. 적중률도 실제 담당자에게 붙는다.
- 반사는 색을 따라가므로 글로 알려줘도 손이 먼저 틀린다. 그게 이 기믹의 전부다 —
  난이도가 아니라 **둘이 서로를 의식하게 만드는 장치**다. "그거 내 거 아냐, 네 거야!"
- 동시류(`owner === -1`)에는 반전이 붙지 않는다. 전원 담당이라 "상대"가 없다.
- 스테이지 2부터. `swapChance` 15% → 스테이지당 +7% → 상한 35%.
- **개인전에도 나온다.** 개인전은 동시류가 없어 플레이어 간 상호작용이 0이었는데,
  반전이 첫 구멍을 낸다(상대 색 노트를 내가 처리해야 하므로 서로를 봐야 한다).
- **레인 도입 후 위치도 함께 거짓말한다.** 반전 노트는 상대 레인에서 등장해 담당 레인으로
  건너온다(`laneAt(k, p)`: p=1 상대 레인 → p=0 담당 레인 선형 보간). 레인이 생기니 위치가
  색보다 강한 신호가 돼서, 담당 레인에 그리면 "저 줄에 있으니 저 사람 것"으로 반전이
  장식이 됐다(플레이테스트 지적). 판정 시점에는 담당 레인에 수렴해 표적 원과 어긋나지 않는다.
- 정직성: 판정선 **표적 원**이 담당 레인에서 빛나고, 노트 안 **키 글자**가 누를 키를 적고,
  **담당 색 점선 링**(`rad + 6`, 파선 5/4)이 노트를 두르고, 차례 안내가 반전을 문장으로
  명시한다. DESIGN.md 원칙 1의 유일한 예외로 명문화했다.
- 표식은 글자가 아니라 모양이다. 초기 구현은 노트 안에 `🔀P2` 를 적었는데 12px 이모지가
  뭉개져 가시성이 나빴다(플레이테스트 지적). 점선 링으로 옮겨 한 노트에 두 색이 겹치게 했다.
- `swapChance` 가 0(미지정)이면 `buildChart` 가 `rnd()` 를 소비하지 않는다 —
  기존 시드 차트가 그대로 재현된다(테스트 보존).

## 판정 모델 (src/systems/mimicry.ts)

- **타깃 절차 생성** — `makeTarget(seed, n)`. 굵은 격자 5×4 칸을 Fisher-Yates 로 셔플해
  앞에서 n개(기본 5) 뽑아 순서대로 잇는다. 칸을 쓰는 이유는 완전 무작위 좌표가 낙서가 되기
  때문이다. 셔플을 쓰는 이유는 중복 재추첨에 무한 루프가 있기 때문이다. 수작업 콘텐츠 0.
- **유사도** — `similarity(a, b)`. 두 그림을 32×24 격자로 래스터화(선분을 칸 대각 기준 ×2로
  샘플링)한 뒤 **1칸 팽창**하고 IoU 를 낸다. 스트로크 순서·굵기·방향은 버린다.
  - 팽창을 넣은 이유: 얇은 선끼리는 한 칸만 어긋나도 교집합이 0이 되어 사람 눈의
    "비슷한데"와 크게 벌어진다. `ponytail:` 팽창 1회 고정 — 여전히 가혹하면 노브로 빼거나
    거리변환으로 바꾼다.
  - 둘 다 빈 그림이면 1, 한쪽만 비었으면 0.
- **스트로크 수명** — `life(s, now, ttl)` 남은 수명 0~1. `ttl <= 0` 이면 사라지지 않는다.
  `relayVisible(strokes, now, ttl)` 은 `born <= now < born + ttl` 인 것만 준다.
- **P1 자기 캔버스는 사라지지 않는다.** 열화는 **중계**에만 걸린다 — 그래야 원본↔P1(전달자의
  성실도)과 P1↔P2(채널 손실)가 각각 의미를 갖고 범인이 갈린다. 둘 다 사라지게 하면
  P1 점수가 P1 의 실력이 아니라 기억력이 되어 층 구분이 무너진다.
- **점수 3개** — `relay`(원본↔P1) · `redraw`(P1↔P2) · `total`(원본↔P2).
  총점만 보여주면 점수는 나오지만 누가 망쳤는지 안 갈린다. 구간을 함께 낸다.

## 판정 모델 (src/systems/pushluck.ts)

- 공유 게이지 `gauge`, 숨은 임계 `limit ∈ [limitMin, limitMax]`. **값은 숨기고 범위는 공개한다.**
  완전 미지는 계산 불가라 체념이 되고 완전 공개는 산수가 된다. 범위 공개가 시청자에게도
  위험을 읽히게 한다(쇼츠 2초 판독의 근거).
- `roll()` — 1d`sides`. `gauge += 눈`, `pot[나] += 눈`. `gauge > limit` 이면 터진다.
- `pass()` — **`rolled` 가 true 일 때만 성공한다.** 게이지는 줄지 않고 차례만 넘어간다.
- 터짐 정산 — 터진 쪽 `pot` 소멸, 상대는 자기 `pot` 을 `score` 로 확보. 게이지·pot 리셋,
  새 `limit`, 라운드 +1. **터진 사람이 다음 라운드를 먼저 시작한다**(벌 위에 선수 불이익을 얹지 않는다).
- `done` — 어느 쪽이든 `target` 도달. 이후 `roll()`/`pass()` 는 무효.

### 설계에서 먼저 막은 두 붕괴

이 둘을 막지 않으면 게임이 성립하지 않는다. 하나만 빼도 한쪽이 지배전략이 된다.

| 붕괴 | 막는 규칙 |
|---|---|
| 넘기기가 공짜면 "항상 즉시 넘기기"가 지배전략 | 차례에 **반드시 한 번 굴려야** 넘길 수 있다 → 넘기기가 회피가 아니라 **공격**이 된다 |
| 굴리기가 순수 손해면 아무도 안 굴린다 | 오른 게이지만큼 **내 pot 도 오른다** |

### 얕음 대응 — 깊이의 출처

- **점수 차이가 정답을 바꾼다.** 쫓기는 쪽은 더 굴려야 하고 앞선 쪽은 확보하려 한다.
  같은 결정이 국면마다 다른 답을 갖는 것이 깊이의 유일한 출처다.
  → 그래서 **생명을 두지 않았다.** 생명으로 지면 점수가 장식이 되어 이 출처가 사라진다.
- **pot 은 라운드가 끝날 때만 확보된다.** 넘길 때 확보하면 넘기기가 지배전략에 가까워지고
  라운드 전체가 걸린 대치가 성립하지 않는다.
- 부수 효과(의도): pot 이 큰 쪽이 더 위험 회피적이 되고 적은 쪽이 자유롭게 굴린다.
  굴리면 pot 이 쌓여 입장이 뒤바뀐다 — 자기 교정되는 국면이라 설계 없이 깊이가 생긴다.

- `modPool` 옵션으로 뽑을 규칙을 제한한다. 테스트는 `["none"]` 으로 고정해 기존 판정을 검증한다.
- **어떤 규칙도 붕괴 방어 2종을 깨지 않는다.**
- **폐기: `nopass`(넘기기 금지).** 그 라운드에서 결정 자체가 사라진다 — 터질 때까지
  굴리는 것 말고 할 게 없고 상대는 가만히 앉아 pot 을 확보한다. 게임이 있어야 할 자리에
  게임이 없어서 뺐다(플레이테스트 지적).
- **되돌리기는 터진 것을 되돌린다.** 살아남은 굴림을 취소하는 건 후회할 일이 없어 드라마가
  안 난다. 구현상 라운드 상태 전부(게이지·pot·점수·차례·임계·라운드·규칙)를 스냅샷한다.
  되돌린 뒤 다시 굴리면 **다른 눈이 나온다** — RNG 는 되감지 않는다. 되감으면 같은 눈이
  또 나와 되돌리기가 무의미해진다.
- **충전은 각자 1회씩이다.** 라운드당 공용 1회로 만들었더니 먼저 쓰는 사람이 상대의 구조
  수단을 보이지 않게 빼앗았다(플레이테스트 지적) — 경쟁 게임에서 그런 비대칭은 전략이
  아니라 불공평으로 읽힌다.
- 스냅샷이 **그 시점의 충전량까지** 담는다. 되돌릴 수 있는지를 살아 있는 상태가 아니라
  스냅샷 자신이 판정하므로, 터진 직후 구조 창구가 열려 있으면서도 새 라운드 충전과 섞이지
  않는다. 다음 굴림이 스냅샷을 덮고 넘기기가 지운다.
- **뜨거운 감자의 +5 는 터짐을 판정하지 않는다.** 아무도 안 굴렸는데 터지면 이상하다.
  임계를 넘겨두면 다음 굴림이 확정으로 터지고 그 책임은 넘긴 사람에게 간다(`passer`).

### 판돈 상승

`stakeMult = 1 + ⌊(round - 1) / 3⌋`. R1~3 ×1, R4~6 ×2 … pot 획득에 곱해진다.
후반 라운드가 자동으로 더 극적이고 역전이 가능해진다.

### 범인 판정 — 이 게임이 클립이 되는 이유

`blame` 3종. 판정은 굴리기 **전에** 잡는다(`rolled` 가 곧 바뀌므로).

| 경우 | `blame` | 화면 문구 |
|---|---|---|
| 상대가 넘겨서 받은 **강제 첫 굴림**에 터짐 | `passer` | "P1 가 넘겼다 — P2 는 강제로 굴려야 했다" |
| 자기 차례 두 번째 이후 굴림에 터짐 | `self` | "P2 가 한 번 더 굴렸다" |
| 라운드 첫 굴림에 터짐(넘김 없이) | `none` | "라운드 첫 굴림 — 그냥 운이 없었다" |

클립이 **두 종류로 번갈아 난다**: 자책(`self`)과 비난(`passer`). 한 종류짜리 구조보다 낫다.

## 화면 — 타들어가는 심지 (PSH-002)

가로 막대로 시작했다가 심지로 바꿨다. 규칙·수치는 그대로고 그리는 것만 다르다.

- **불꽃 위치 = 게이지.** 굴릴 때마다 불꽃이 폭탄 쪽으로 전진한다.
  뒤(지나온 구간)는 재(`C.line`), 앞은 성한 심지(`C.textMuted`)로 그린다.
- **붉은 구간 = 임계 범위.** 심지 뒤에 굵고 흐린 띠로 깔아 "이 안 어딘가에서 끊긴다"를
  그림으로 말한다. 불꽃이 그 구간에 들어가면 불꽃이 `C.danger` 로 바뀌고 경고음이 난다 —
  색·위치·소리 세 채널이 같이 말한다.
- **폭발은 심지가 끊긴 그 자리에서 난다.** 끝의 폭탄에서 터지게 하면 "끝까지 가야
  터진다"로 읽혀 숨은 임계값이라는 규칙과 어긋난다. `newRound` 가 게이지를 0 으로
  되돌리므로 씬이 터진 게이지를 따로 기억한다.
- 끝의 폭탄은 **도달하지 않는 게 정상이다.** 남은 심지가 여유로 읽힌다.
- 심지는 `sin` 으로 살짝 물결지게 그린다. 진폭 5 — 크면 불꽃 위치가 흐려져
  장식이 판정을 가린다(원칙 5).
- 불꽃 지글거림은 **반지름 흔들림**으로 낸다. 파티클 배열을 새로 만들지 않았다.
- 굴린 눈을 크게 팝시킨다(punchline 시각).
- 넘기기 버튼은 `canPass` 가 false 면 비활성 + "먼저 한 번 굴려야 한다" 를 적는다.
  굴리기 전에 누르면 거절 문구가 잠깐 뜬다.
- 터질 때 화면 흔들림 + 붉은 가장자리 + 범인 문구 + "N점 소멸 · 상대가 M점 확보".
- **이번 라운드 규칙 배너**를 제목 아래 띄운다. 기본이면 흐리게, 규칙이 붙으면 `C.accentHi` 로.
- 안개 라운드는 붉은 띠·눈금·범위 문구를 전부 가린다.
- 되돌리기 버튼은 **그 규칙의 라운드에만, 남았을 때만** 나타난다(`Z` 키 병행).
- 연발은 주사위에 합을 크게, 그 아래 `3 + 5` 로 무엇이 합쳐졌는지 적는다.
- **폭발 확률은 표시하지 않는다.** 계산이 가능해지면 도박이 아니라 스프레드시트가 된다.

## 판정 모델 (src/systems/zerosum.ts)

**이 게임의 전부는 불변식 하나다: 내 칸 + 네 칸 = 140, 언제나.**
빈 칸이 생기는 순간 제로섬이 아니게 되고 막대 하나로 판세를 보여주는 것도 불가능해진다.
테스트가 매 수마다 이 불변식을 확인한다.

- **처음부터 꽉 찬 판.** 70:70. 1턴부터 모든 수가 순수한 강탈이다.
- **시작 배치 5종**(ZRO-003). 매판 하나를 뽑는다 — 항상 좌우로 시작하면 첫 몇 수가
  늘 같은 최적수가 되고 판이 다르게 흘러갈 여지가 거기서부터 좁아진다.

  | id | 이름 | 배치 |
  |---|---|---|
  | `split` | 좌우 | 왼쪽 절반 / 오른쪽 절반 |
  | `stack` | 상하 | 위 절반 / 아래 절반 |
  | `quad` | 사분 | 좌상+우하 / 우상+좌하 |
  | `rows` | 가로줄 | 짝수 행 / 홀수 행 |
  | `cols` | 세로줄 | 짝수 열 / 홀수 열 |

  다섯 다 **산식만으로 정확히 70:70** 이고(정렬해서 앞 절반을 자르면 무늬가 깨진다),
  **좌우 또는 상하로 뒤집으면 P1 영역이 P2 영역이 된다**(대등성). 가운데/바깥 배치는
  중앙이 구조적으로 유리해서 대등성을 못 지키므로 뺐다.
  줄무늬 배치는 처음부터 섞여 있어 어디를 쳐도 뺏는다 — 좌우 배치와 완전히 다른 판이 된다.
- **모양 7종**(ZRO-002). 라운드마다 하나를 뽑아 클릭 **전에** 보여준다.
  뒤에 알려주면 결정이 사라지고 그냥 운이 된다. 랜덤(모양)과 결정(자리)이 분리된다 —
  떠넘기기(CON-003)와 같은 구조다.

  | id | 이름 | 모양 | 칸 |
  |---|---|---|---|
  | `plus` | 십자 | 팔 1 십자 | 5 |
  | `hbar` | 막대 | 가로 1×7 | 7 — 깊이 찌른다 |
  | `vbar` | 기둥 | 세로 7×1 | 7 — 경계를 따라 훑는다 |
  | `box` | 네모 | 3×3 | 9 |
  | `star` | 별 | 다이아몬드 r2 | 13 |
  | `cross` | 큰십자 | 팔 3 십자 | 13 |
  | `ring` | 고리 | 5×5 테두리(가운데 빔) | 16 |

- **모든 모양이 점대칭이다.** 비대칭 모양(L·T·S)을 넣으면 회전 조작이 필요해지고
  조작 1종(클릭)이라는 이 게임의 강점이 깨진다. 회전이 없으면 방향 운도 없다.
- **한 라운드(P1 한 수 + P2 한 수)는 둘 다 같은 모양을 쓴다.** 모양은 라운드가 바뀔 때
  새로 뽑는다. 제로섬은 파이가 고정이라 **운의 비대칭이 그대로 승패가 되고 만회할 여지가
  규칙에 없다** — 나눠 쓰면 운은 "무슨 모양이 오나"에만 남고 실력은 "어디 놓나"로 온전히 간다.
- **고리는 가운데를 비운다.** 이미 내 칸인 중심을 낭비하지 않고 상대 영역만 훑는 모양이라
  되받아치기와 다른 결이 나온다.
- 판 경계 밖은 버린다.
- **판세 궤적** — `history` 가 시작 상태부터 매 수의 `{player, own0, taken}` 을 쌓는다.
  총합이 고정이라 **P1 칸 수 하나**로 판세가 완전히 표현된다(P2 는 여집합이므로 선 두 개는
  같은 정보를 두 번 그리는 것이다). `bestMove()` 가 가장 많이 뺏은 수를 돌려준다.
- `claim()` 은 `taken`(실제로 뺏은 칸)과 `kept`(이미 내 칸이었던 낭비분)를 나눠 돌려준다.
  되받아칠수록 `kept` 가 늘어 이득이 줄어든다 — 핑퐁이 저절로 잦아드는 근거다.
- **매 턴 끝에 자기 칸 수만큼 점수.** 매 수마다 양쪽 점수 합이 정확히 140이다
  (제로섬, 정확히는 상수합 — 전략적으로 동치).

### 설계에서 먼저 막은 붕괴

| 붕괴 | 막는 규칙 |
|---|---|
| 최종 판만 세면 **마지막에 두는 사람이 유리**하다(반격을 안 받는다) | 매 턴 점수 — 오래 들고 있는 것이 값이 된다 |
